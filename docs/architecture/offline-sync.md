# Offline-first and synchronization

The app is designed to work without an internet connection. This page explains how data is stored locally and how it is synchronized with the backend when a network connection is available.

## Local storage — `LocalDatabase`

`lib/src/core/storage/local_database.dart` is a singleton that wraps `sqflite` (on mobile and desktop) and IndexedDB (on Web).

**Schema of the `local_patients` table:**

```sql
CREATE TABLE local_patients (
  patient_id    TEXT PRIMARY KEY, -- UUID v4 generated by the frontend
  device_uid    TEXT NOT NULL, -- NFC device UID
  patient_name  TEXT NOT NULL, -- Name to display in the UI (masked)
  record_json   TEXT NOT NULL, -- PatientFullRecord serialized as JSON (encrypted)
  is_synced     INTEGER NOT NULL DEFAULT 0, -- 0 = pending, 1 = synchronized
  sync_error    TEXT, -- Message of the last sync error
  sync_error_code INTEGER, -- HTTP status code of the last sync error
  created_at    TEXT NOT NULL, -- ISO 8601
  synced_at     TEXT, -- ISO 8601 — null until the first successful sync
  revision      INTEGER NOT NULL DEFAULT 0,
  owner_user_id TEXT,
  organization_id TEXT,
  pending_retired_reason TEXT
)
```

!!! note "Almacenamiento en Web"
sqflite is not available in Flutter Web. LocalDatabase uses IndexedDB
(backed by hwb_local_store) as its persistence layer on Web, not just a
development fallback — it is the production storage path for this
platform. Encryption keys on Web are kept in sessionStorage (so ciphertexts
in IndexedDB become unreadable upon closing the tab/session). Clinical payloads
(record_json) are encrypted with AES-256-GCM before being written, the index
patient_name column is masked (e.g. "Ana G.") rather than stored in full,
and the break-glass emergency log encrypts patient_name/user_id the same way.
See web/index.html's Content-Security-Policy for the defense-in-depth layer.

## Synchronization Engine — SyncEngine
lib/src/core/sync/sync_engine.dart implements the background synchronization cycle.

### Lifecycle

```dart
// Start connectivity monitoring
syncEngine.start();

// Stop (example, on logout)
syncEngine.stop();
```

### Synchronization Flow

```
Connectivity Detected (via connectivity_plus)
        │
        ▼
getUnsyncedRecords()   ← list local_patients WHERE is_synced = 0 AND owner_user_id = current_user
        │
        ▼ (for each record)
POST /api/v1/patients/sync
        │
   ┌────┴────┐
   │  201    │  → markSynced(patientId)   → removes the row from local storage
   │  4xx    │  → markSyncError(message)  → permanent error (holds/blocks row for review)
   │  5xx    │  → markSyncError(message)  → automatic retry
   │  401    │  → stop sync               → redirect to login
   └─────────┘
```

### Behavior by Error Code

| Code | Action |
|---|---|
| 201 | Marks as synchronized and deletes the row from local storage (markSynced)Marks as synchronized and deletes the row from local storage (markSynced) |
| 400 / 403 / 409 / 422 | Permanent error — holds row as blocked for review or user resolution |
| 401 | Stops synchronization entirely — token expired, requires re-login |
| 429 / 500 | Keeps is_synced = 0 for automatic retry |
| Timeout | Keeps is_synced = 0 for automatic retry |

### Callbacks

```dart
syncEngine.onSyncStatusChanged = (int unsyncedCount) {
  // Update badge/counter in the UI
};

syncEngine.onRecordSynced = (String patientId, bool success, String? error) {
  // React to the synchronization of a specific record
};
```

## Scrubbing of Clinical Data

Once a record is successfully synchronized with the backend (HTTP 201), the app removes the entry from local storage (markSynced deletes the row in local_patients).

This protects patient privacy in case of device loss or theft.

## Connectivity

SyncEngine subscribes directly to network change events via connectivity_plus (WiFi, mobile data) and probes backend reachability using Reachability.probe(). Upon regaining connection to a valid server, it automatically triggers syncAll().
