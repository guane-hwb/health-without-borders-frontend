# Offline-first and synchronization

The app is designed to work without an internet connection. This page explains how data is stored locally and how it is synchronized with the backend when a network connection is available.

## Local storage — `LocalDatabase`

`lib/src/core/storage/local_database.dart` is a singleton that wraps `sqflite`.

**Schema of the `local_patients` table:**

```sql
CREATE TABLE local_patients (
  patient_id TEXT PRIMARY KEY, -- UUID v4 generated by the frontend
  device_uid TEXT NOT NULL, -- NFC wristband UID
  patient_name TEXT NOT NULL, -- Name to display in the UI
  record_json TEXT NOT NULL, -- PatientFullRecord serialized as JSON
  is_synced INTEGER NOT NULL DEFAULT 0, -- 0 = pending, 1 = synchronized
  sync_error TEXT, -- Message of the last sync error
  created_at TEXT NOT NULL, -- ISO 8601
  synced_at TEXT -- ISO 8601 — null until the first successful sync
)
```

!!! note "Fallback web"
    `sqflite` is not available in Flutter Web. `LocalDatabase` uses an in-memory `Map<String, Map<String, dynamic>>` as a fallback for Chrome development. For web production, `sqflite_common_ffi_web` would be required.

## Synchronization Engine — `SyncEngine`

`lib/src/core/sync/sync_engine.dart` implements the background synchronization cycle.

### Lifecycle

```dart
// Start connectivity monitoring
syncEngine.start();

// Stop (example, on logout)
syncEngine.stop();
```

### Synchronization Flow

```
Connectivity Detected
        │
        ▼
getUnsyncedRecords()   ← list local_patients WHERE is_synced = 0
        │
        ▼ (for each record)
POST /api/v1/patients/sync
        │
   ┌────┴────┐
   │  201    │  → markSynced(patientId)   → scrub of clinical data
   │  4xx    │  → markSyncError(message)  → hold for review
   │  5xx    │  → markSyncError(message)  → automatic retry
   │  401    │  → detener sync            → redirect to login
   └─────────┘
```

### Behavior by Error Code

| Code | Action |
|---|---|
| 201 | Marks as synchronized, deletes clinical data from the local record |
| 400 / 422 | Does not retry — data error, user should review |
| 401 | Stops synchronization entirely — token expired, requires re-login |
| 429 / 500 | Keeps `is_synced = 0` for automatic retry |
| Timeout | Keeps `is_synced = 0` for automatic retry |

### Callbacks

```dart
syncEngine.onSyncStatusChanged = (int unsyncedCount) {
  // Update badge/counter in the UI
};

syncEngine.onRecordSynced = (String patientId, bool success, String? error) {
  // React to the synchronization of a specific record
};
```

## Scrubbing of Clinical Data

Once a record is successfully synchronized with the backend, the app removes the clinical data from local storage (the `record_json` field) for security reasons. It only retains the metadata: `patient_id`, `device_uid`, `patient_name`, `is_synced`, `synced_at`.

This protects patient privacy in case of device loss or theft.

## Connectivity

`lib/src/core/network/connectivity_service` uses `connectivity_plus` to detect network changes (WiFi, mobile data). The `SyncEngine` subscribes to these events and automatically calls `syncAll()` upon regaining a connection.
