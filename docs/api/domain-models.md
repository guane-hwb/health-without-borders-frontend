# Domain Models

The models in `lib/src/features/nfc/domain/patient_record.dart` are a 1:1 mirror of the backend Python schemas (`app/schemas/patient.py`). **Any changes to the backend must be reflected here.**

Regulatory reference: Resolutions 866/2021 and 1888/2025 of the Colombian Ministry of Health (RDA — Digital Registry in Care).

---

## `PatientFullRecord`

Root model. This is the body of `POST /api/v1/patients/sync` and the response of `GET /api/v1/patients/scan/{device_uid}`.

```dart
class PatientFullRecord {
  final String patientId;          // UUID v4 generated by the frontend
  final String deviceUid;          // NFC device UID (hardware)
  final PatientInfo patientInfo;
  final GuardianInfo guardianInfo;
  final BackgroundHistory? backgroundHistory;
  final List<AllergyInfo> allergies;
  final List<MedicalHistoryItem> medicalHistory;
  final List<VaccinationRecordItem> vaccinationRecord;
}
```

---

## `PatientInfo`

Patient demographics (Elems 1–13 of Res. 866).

| Field | Type | Description |
|---|---|---|
| `identification` | `PatientIdentification` | Document type and number |
| `firstLastName` | `String` | First surname (Elem. 3.1) |
| `secondLastName` | `String?` | Second surname (Elem. 3.2) |
| `firstName` | `String` | First name (Elem. 3.3) |
| `secondName` | `String?` | Middle name (Elem. 3.4) |
| `dob` | `String` | Date of birth `YYYY-MM-DD` (Elem. 4) |
| `biologicalSex` | `String` | `"M"`, `"F"`, `"I"` (Elem. 5) |
| `genderIdentity` | `String?` | `"01"`–`"04"`, `"99"` (Elem. 6) |
| `ethnicity` | `String?` | `"01"`–`"06"` (Elem. 13.1) |
| `nationalityCode` | `String` | ISO 3166-1 alpha-3, default `"COL"` |
| `address` | `Address` | Residential Address |
| `bloodType` | `String?` | Blood Type |
| `weight` / `height` | `double?` | Weight (kg) / Height (cm) |

**Supported Document Types:** `CC`, `CE`, `PA`, `RC`, `TI`, `SC`, `PE`, `PT`, `MS`, `AS`, `CN`, `DE`.

## `BackgroundHistory`

Personal and Family History.

```dart
class BackgroundHistory {
  final String? chronicConditions;       // Chronic conditions (free text)
  final String? personalHistory;         // Personal history (free text)
  final List<FamilyHistoryItem> familyHistory;
  final String? familyHistoryNotes;
}
```

### `FamilyHistoryItem`

The frontend sends `conditionDescription` (free text) and `relationship`. The backend resolves the ICD-10 and ICD-11 codes using LLM.

| Code `relationship` | Meaning |
|---|---|
| `"01"` | Parents |
| `"02"` | Brothers |
| `"03"` | Aunts/Uncles |
| `"04"` | Grandparents |

## `VaccinationRecordItem`

```dart
class VaccinationRecordItem {
  final String date;             // YYYY-MM-DD
  final String vaccineName;
  final String vaccineCode;      // CVX Code

  final String administratedBy;
  final String administratedAt;
  final String status;           // "completed" by default

```

## `MedicalHistoryItem`

A clinical query (RDA-Query, Res. 866).

The `diagnosis` and `riskFactors` fields are sent as empty lists from the frontend; the backend resolves them using LLM based on `clinicalEvaluation`.

**Key Fields:**

| Field | Values ​​|
|---|---|
| `careModality` | `"01"`–`"09"` |
| `serviceGroup` | `"01"`–`"05"` |
| `careEnvironment` | `"01"`–`"05"` |
| `diagnosisType` | `"01"` Confirmed, `"02"` Presumptive, `"03"` Discarded |
| `dischargeDisposition` | `"01"`–`"04"` |

## `PatientSyncResponse`

Response from `POST /api/v1/patients/sync`:

```dart
class PatientSyncResponse {
  final String status;       // "success" or "error"
  final String internalId;   // Internal backend ID
  final String? fhirStatus;  // FHIR integration status
  final String? vidaCode;    // VIDA code (national system)
  final String message;
}
```
